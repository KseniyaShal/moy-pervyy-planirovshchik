# Техническое задание «планировщик-мотивировщик»

Версия документа 1.7. Дата 17.10.2026.

## 1. Назначение и статус документа

Разработать личный планировщик тренировок на неделю. Пользователь планирует занятия, отмечает фактическую продолжительность, переносит тренировки и получает сравнение недельного плана с результатом и поддерживающие сообщения.

Приложение ориентировано на телефон, но должно работать и на компьютере. Интерфейс на русском языке, обращение на «ты». Стиль уютный, пастельный. Эмодзи и доброжелательный юмор приветствуются.

Этот документ фиксирует согласованные требования к первой версии. Реализация и фактические результаты итоговой проверки описаны в plan.md.

ТЗ учитывает ответы пользователя и уточняет первоначальную концепцию в `concept.md`. При расхождении документов требования этого ТЗ имеют приоритет. В частности, перенос разрешён для запланированных и пропущенных тренировок, а в итогах показываются план и факт.

### 1.1. Основание требований

Продуктовые требования взяты из ответов пользователя в этом чате. Ограничения полей, тексты интерфейса, модель данных и правила обработки ошибок ниже являются принятыми проектными решениями для первой версии, а не результатами отдельного исследования.

Не оставлять в реализации заглушки, неработающие кнопки, демонстрационные тренировки или функции, требующие последующего выбора пользователя. Данные первого запуска должны быть пустыми.

## 2. Состав приложения и ограничения

Готовое приложение состоит ровно из трёх файлов в одной папке.

| Файл | Назначение |
| --- | --- |
| `index.html` | Структура страницы, формы и диалоги |
| `style.css` | Оформление и адаптация под размеры экрана |
| `script.js` | Поведение, расчёты, сообщения и сохранение |

Технические требования.

- Использовать обычные HTML, CSS и JavaScript без фреймворков и сборки.
- Подключать CSS и JS относительными путями. JS подключать как обычный внешний скрипт с `defer`, без модулей.
- Все пользовательские данные хранить через localStorage. Не использовать сервер, базу данных, аккаунты или внешние API.
- Не использовать CDN, внешние шрифты, библиотеки, изображения, аналитику и сетевые запросы.
- Использовать системный шрифт и текстовые эмодзи. Дополнительные файлы ресурсов не создавать.
- Для работы после загрузки файлов интернет не требуется.
- `concept.md` и `tz.md` являются документацией и не входят в число трёх файлов приложения.
- Открытие `index.html` не должно требовать установки пакетов или запуска серверной части.

### 2.1. Граница гарантии хранения

Сохранение должно работать в браузерном окружении, предоставляющем доступ к localStorage. Для страниц, открытых через `file:`, поведение localStorage не определено одинаково для всех браузеров. Прямое открытие файла на каждом телефоне нельзя считать гарантированным способом запуска. Это ограничение среды, которое нельзя устранить обещанием в интерфейсе. [Источник - MDN, localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

Не добавлять сервер как обходной путь. При недоступном хранилище действуют правила раздела 12. Проверять фактическое сохранение при приёмке в выбранном браузере и способе открытия страницы.

## 3. Пользователи и права

В продукте одна роль - пользователь своего локального планировщика.

Нет регистрации, входа, администратора, тренера, приглашённых участников и совместного доступа. Все действия доступны пользователю сразу после открытия страницы, кроме действий, ограниченных датой, состоянием тренировки или ошибкой хранения.

Пользователь может.

- Просматривать текущую, прошлые и будущие недели.
- Создавать несколько тренировок на один день, включая прошедшие даты.
- Редактировать название, дату и планируемую продолжительность.
- Вносить и исправлять фактическое время начиная с даты занятия.
- Отмечать пропуск начиная с даты занятия.
- Заменять пропуск выполнением, а выполненную тренировку пропуском.
- Сбрасывать результат до состояния «запланировано».
- Переносить запланированные и пропущенные тренировки.
- Удалять отдельные тренировки после подтверждения.
- Удалять все данные планировщика после подтверждения и отдельной отметки о понимании последствий.
- Смотреть итоги выбранной недели и поддерживающие сообщения.

Данные относятся к браузеру и месту открытия страницы. Синхронизация между устройствами не входит в продукт. Очистка данных браузера может удалить записи. [Источник - MDN, localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

## 4. Структура главной страницы

Главная страница одна, без маршрутов и отдельных экранов статистики.

Элементы сверху вниз.

1. Заголовок «планировщик-мотивировщик».
2. Подзаголовок «планируй движение, отмечай результат, поддерживай себя 🌿».
3. Диапазон выбранной недели.
4. Кнопки «предыдущая неделя», «текущая неделя», «следующая неделя».
5. Список семи дней от понедельника до воскресенья.
6. Блок «итоги недели».
7. Подвал с подписью «данные сохраняются в этом браузере» и второстепенной кнопкой «очистить все данные».

В каждом дне показываются название дня недели, дата, карточки и кнопка «добавить тренировку». Сегодняшний день отмечается подписью «сегодня» и мягким цветовым акцентом. Если карточек нет, показывается текст «пока без тренировок».

Список всегда вертикальный и включает все семь дней. Не заменять его календарной сеткой или просмотром только одного дня. Пустые дни не скрывать.

### 4.1. Пустые состояния

- У пустого дня показывать компактную карточку с текстом «пока без тренировок» и обычной кнопкой «добавить тренировку». Дополнительная иконка или иллюстрация не требуется.
- Если вся выбранная неделя пустая, над списком дней показывать «на эту неделю пока ничего не запланировано 🌿» и кнопку «запланировать тренировку».
- Эта кнопка открывает обычную форму добавления. Для текущей недели предвыбирать сегодня, для прошлой или будущей - понедельник выбранной недели. В граничной неделе использовать первый допустимый день.
- Не скрывать семь дней и нулевые итоги даже при пустой неделе.
- Для первого запуска и перехода к другой пустой неделе использовать одинаковое оформление.
- После добавления первой записи убрать недельное пустое состояние. После удаления последней или очистки данных вернуть его.

Даты отображаются по-русски. Диапазон недели показывать с годом, например «12-18 октября 2026». При переходе через месяц или год явно показывать обе границы, например «28 декабря 2026 - 3 января 2027».

### 4.2. Навигация и сортировка

- При каждом полном открытии страницы выбирать текущую неделю. Последнюю просмотренную неделю не сохранять.
- При открытии и перезагрузке выделять «Текущая неделя». При просмотре любой прошлой недели выделять «Предыдущая неделя», любой будущей - «Следующая неделя». Одновременно выделена ровно одна плашка.
- Выделение определять по дате начала открытой недели относительно текущей календарной недели, а не по последней нажатой кнопке. Переход вперёд из далёкой прошлой недели оставляет выделенной «Предыдущая неделя», пока выбранная неделя остаётся прошлой. Симметрично для движения назад из будущего.
- Выделение обновлять при любом изменении отображаемой недели, включая создание или исправление даты тренировки, а также при проверке смены календарного дня. Саму выбранную неделю при смене дня не переключать автоматически.
- Только выбранной плашке задавать `aria-current="true"`. Цвет выделения отделить от оформления регистра текста, чтобы надписи сохраняли правила раздела 13.1.
- Кнопки предыдущей и следующей недели сдвигают начало недели ровно на семь календарных дней.
- «текущая неделя» возвращает к неделе сегодняшнего дня. Если она уже открыта, кнопка остаётся доступной и прокручивает к заголовку недели.
- При обычном переключении недели прокручивать к заголовку недели.
- Внутри дня сортировать карточки по `createdAt` по возрастанию, затем по `id`. Изменение и перенос не меняют `createdAt`.
- Не создавать отдельные сохранённые объекты недель. Дни и итоги вычислять из списка тренировок.

## 5. Даты и продолжительность

### 5.1. Правила дат

- Неделя начинается в понедельник и заканчивается в воскресенье.
- Сегодняшнюю дату брать из локальной даты устройства. Часовой пояс приложения отдельно не настраивается и не фиксируется на одном городе.
- Запланированную дату хранить календарной строкой `YYYY-MM-DD`, без времени и часового пояса.
- Проверять, что дата действительно существует. Не принимать, например, 31 февраля.
- Не получать календарную дату через UTC-преобразование `toISOString().slice(0, 10)`.
- Для сравнения использовать валидные календарные даты. Для сдвига дней и недель использовать календарные операции, а не прибавление фиксированного количества миллисекунд.
- Диапазон допустимых дат первой версии от 01.01.1900 до 31.12.2099 включительно. Это технический диапазон интерфейса, а не ограничение по типу тренировок.
- Не заменять его скользящим диапазоном относительно текущего года. Старые записи должны оставаться доступны через несколько лет. Все формы по умолчанию открываются на выбранном дне или текущем периоде, а не на границе технического диапазона.
- Граничные недели показывать полностью, но у дней вне допустимого диапазона отключать добавление с подписью «дата вне доступного диапазона».
- Отключать навигацию к неделе, в которой нет ни одной допустимой даты.
- Перепроверять сегодняшнюю дату перед сохранением результата, пропуском и переносом, при возвращении на вкладку и раз в минуту.
- После смены даты обновлять отметку «сегодня», доступность действий и сообщения. Выбранную неделю автоматически не переключать. Для возврата есть кнопка «текущая неделя».

### 5.2. Выбор даты в интерфейсе

Использовать нативный `<input type="date">`, без собственного календаря и выпадающих списков дней, месяцев и лет. У каждого такого поля есть видимая подпись, `required`, `step="1"` и границы `min` и `max`.

| Форма и состояние | `min` | `max` |
| --- | --- | --- |
| Создание | `1900-01-01` | `2099-12-31` |
| Редактирование запланированной | `1900-01-01` | `2099-12-31` |
| Исправление выполненной или редактирование пропущенной | `1900-01-01` | Сегодня, но не позже `2099-12-31` |
| Перенос запланированной или пропущенной | Сегодня, но не раньше `1900-01-01` | `2099-12-31` |

При открытии формы и перед сохранением актуализировать границы. Если допустимого интервала нет, отключить соответствующее действие с пояснением «дата вне доступного диапазона».

Внешний вид и формат отображения нативного календаря зависят от браузера и языка устройства. В данных использовать нормализованное значение `YYYY-MM-DD`. Не требовать визуально одинакового календаря на iPhone и компьютере. HTML-ограничения дополняют, но не заменяют проверки JavaScript. [Источник - MDN, поле даты](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/date).

### 5.3. Правила продолжительности

План и факт вводятся отдельными полями «часы» и «минуты», но представляют одну продолжительность.

- Часы являются целым числом от 0 до 24.
- Минуты являются целым числом от 0 до 59.
- Пустое поле часов или минут при сохранении трактовать как 0.
- Итоговая продолжительность рассчитывается как часы × 60 + минуты.
- Для плана и выполненной тренировки допустимо от 1 до 1440 минут включительно. При 24 часах минуты должны быть равны 0.
- Отрицательные числа, дроби, экспоненциальную запись, буквы и другие нечисловые значения не принимать. Не округлять и не исправлять их незаметно.
- Нулевое фактическое время не сохранять как выполнение. Предложить действие «отметить пропуск».
- Хранить продолжительность целым числом минут. Недельная сумма может превышать 1440 минут.

Показывать человекочитаемую продолжительность с правильными окончаниями, например «1 минута», «45 минут», «1 час», «1 час 5 минут», «2 часа 30 минут», «5 часов». Нулевую продолжительность показывать как «0 минут». Незаполненный факт показывать как «ещё не отмечено».

## 6. Карточки и состояния тренировок

Карточка содержит название активности, планируемую продолжительность, фактическую продолжительность и текстовое состояние. Дата видна в заголовке дня; её повторение внутри карточки не требуется.

| Состояние в данных | Подпись | Значение `actualMinutes` |
| --- | --- | --- |
| `planned` | «запланировано» | `null` |
| `completed` | «выполнено» | Целое число от 1 до 1440 |
| `skipped` | «пропущено» | `0` |

Нельзя хранить состояние `completed` с нулём, состояние `planned` с фактическим временем или состояние `skipped` с положительным временем.

Прошедшая дата не переводит тренировку в пропущенную автоматически. У запланированной тренировки с датой раньше сегодняшней показывать дополнительную подпись «ожидает отметки». Это подсказка интерфейса, а не четвёртое состояние.

Занятие с фактом меньше плана, но больше нуля, считается выполненным и добавляет одно занятие в итог недели.

### 6.1. Доступные действия

| Карточка | Действия |
| --- | --- |
| Запланированная, дата в будущем | «редактировать», «перенести», «удалить» |
| Запланированная, дата сегодня или раньше | «отметить результат», «пропустить», «редактировать», «перенести», «удалить» |
| Выполненная | «изменить результат», «исправить запись», «сбросить отметку», «удалить» |
| Пропущенная | «отметить результат», «редактировать», «перенести», «сбросить отметку», «удалить» |

Для выполненной тренировки действие замены на пропуск доступно в форме изменения результата. «Перенести» означает запланировать занятие заново на сегодня или будущее и убрать его прежнюю отметку. Это действие не применяется к уже состоявшемуся занятию.

«Исправить запись» открывает форму основных полей выполненной тренировки и позволяет исправить ошибочную дату на сегодня или прошлую дату, сохранив фактическое время. У поля даты показывать «исправление даты сохранит результат и учтёт его в неделе новой даты». Это корректировка записи о состоявшемся занятии, а не повторное планирование.

Состояния и действия различать текстом. Цвет не должен быть единственным обозначением результата.

## 7. Формы и операции

Все формы и подтверждения открываются поверх главной страницы в нативном `<dialog>`, через `.showModal()`; закрываются через `.close()`. Не создавать собственную систему модальных окон. На телефоне допустим диалог почти на всю ширину экрана с собственной вертикальной прокруткой. Одновременно открыта только одна форма или одно подтверждение.

У каждой формы есть заголовок, подписанные поля, основное действие, «отмена» и отдельная кнопка закрытия с символом «✕», `type="button"` и `aria-label="закрыть"`. Кнопка закрытия имеет такую же доступную область нажатия, как остальные кнопки, и не отправляет форму.

Закрытие крестиком, кнопкой «отмена», Escape или нажатием на фон означает отмену. Несохранённый ввод не записывается. После закрытия вернуть фокус на вызвавшую кнопку, если она существует, иначе на заголовок соответствующего дня; у подтверждения общей очистки - на кнопку в подвале.

Нельзя закрывать форму по клику внутри неё. Ошибки показывать около поля; фокус переносить на первое ошибочное поле. После ошибки сохранения введённые значения сохранять в открытой форме.

Нативный диалог обеспечивает модальное поведение и обработку Escape, но начальный фокус, подписи и возврат фокуса всё равно необходимо проверить. Закрытие по фону реализовать отдельно, только если нажатие началось и закончилось вне прямоугольника содержимого диалога. Не полагаться на новое браузерное поведение автоматического закрытия по фону. [Источник - MDN, dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog).

Если подтверждение вызывается из формы, переключать содержимое того же диалога без вложенного модального окна. При отказе от подтверждения восстанавливать исходную форму и её ввод. Escape, крестик и фон в этом подтверждении также означают отказ и возврат в форму.

Для форм ввода использовать `novalidate`, чтобы показывать заданные в разделе 12 сообщения, а не разные браузерные всплывающие ошибки. При этом задавать HTML-атрибуты ограничений и проверять значения в JavaScript. Обработчик отправки отменяет обычную отправку формы. Не использовать автоматическое закрытие через `method="dialog"` для сохранения данных. Закрывать диалог только после успешной записи; кнопки отмены закрывают его независимо от ошибок заполнения.

### 7.1. Создание тренировки

Кнопка «добавить тренировку» находится у каждого дня. Заголовок формы «новая тренировка».

| Поле | Начальное значение | Правила |
| --- | --- | --- |
| «активность» | Пусто | Обязательное, от 1 до 80 символов после нормализации |
| «дата» | Дата выбранного дня | Обязательная допустимая дата, включая прошлое |
| «планируемая продолжительность» | 0 часов 30 минут | Правила раздела 5.3 |

У названия удалить пробелы по краям, а последовательности пробельных символов внутри заменить одним пробелом. Длину считать по Unicode-кодовым точкам, чтобы эмодзи не обрезались посередине. Разрешать одинаковые названия у разных записей.

Основная кнопка «добавить». После успешного сохранения создать одну запись со статусом `planned` и фактом `null`, закрыть форму и показать «тренировка добавлена 🌿».

Перейти к неделе введённой даты, если она отличается от открытой, и прокрутить к созданной карточке. Подсветить карточку на 2 секунды. Не создавать дубликат при повторном нажатии на кнопку сохранения.

Создание задним числом не меняет набор полей. Сначала создаётся план, затем через «отметить результат» вносится факт. Пользователь сама выбирает планируемую продолжительность для такой записи; приложение не подставляет факт вместо плана.

### 7.2. Редактирование основных полей и исправление записи

Форма «редактировать тренировку» содержит те же три поля, заполненные текущими значениями. Для выполненной тренировки её заголовок и вызывающая кнопка называются «исправить запись». Основная кнопка в обоих случаях «сохранить изменения».

- У запланированной тренировки дата может быть прошлой, сегодняшней или будущей.
- У выполненной или пропущенной тренировки исправленная дата не может быть позже сегодняшней. Для планирования пропущенной на будущую дату используется «перенести».
- Редактирование названия, плана и допустимой даты сохраняет состояние и фактическое время.
- Изменение планируемого времени пересчитывает сравнение плана с фактом и сообщение, но не переписывает фактическую продолжительность.
- После исправления даты запись показывается в соответствующем дне и неделе с прежними состоянием и фактом. Итоги исходной и новой недель вычисляются заново.
- Сохранять `id` и `createdAt`, обновлять `updatedAt`.
- После сохранения показать «изменения сохранены» и перейти к карточке по правилам создания.
- Если ни одно значение не изменилось, закрыть форму без записи в хранилище и без сообщения об изменениях.

### 7.3. Ввод и исправление результата

Форма «результат тренировки» показывает название, дату, план и поля «фактическая продолжительность».

- Для выполненной тренировки предзаполнять существующий факт.
- Для запланированной или пропущенной тренировки начальные значения 0 часов 0 минут. Не подставлять планируемое время как якобы фактическое.
- Основная кнопка «сохранить результат».
- При положительной валидной продолжительности установить `completed` и сохранить фактические минуты.
- При нуле показать «укажи время больше нуля или отметь пропуск». Не менять запись автоматически.
- Действие «отметить пропуск» доступно для запланированной и выполненной записи в этой форме.
- Если выполненная запись заменяется пропуском, сначала спросить «заменить результат пропуском? записанное фактическое время будет удалено» с кнопками «заменить» и «отмена».
- При сохранении проверить, что дата тренировки не позже сегодняшней.
- После успеха закрыть форму, обновить карточку и итог, показать сообщение по результату из раздела 10.
- Если положительный факт не изменился, закрыть форму без повторной записи и без нового уведомления.

### 7.4. Отметка пропуска

У запланированной тренировки на сегодня или прошлую дату кнопка «пропустить» сразу устанавливает `skipped` и факт `0`. Отдельное подтверждение не требуется, поскольку результат можно исправить.

Показать утешительное сообщение и сохранить доступную кнопку «перенести». Не переносить тренировку автоматически и не удалять её.

Повторная отметка того же пропуска не должна создавать новую запись или повторно изменять данные.

### 7.5. Сброс результата

У выполненных и пропущенных тренировок действие «сбросить отметку» открывает подтверждение «сбросить отметку? тренировка снова станет запланированной».

Кнопки «сбросить» и «отмена». После подтверждения оставить дату, название и план, установить `planned` и факт `null`. Записать изменение и показать «отметка сброшена». Итоги и сообщения обновить.

Это действие не удаляет тренировку и не переносит её.

### 7.6. Перенос

Перенос разрешён для `planned` и `skipped`. Форма «перенести тренировку» показывает название, исходную дату и план. Единственное редактируемое поле «новая дата».

- Новую дату по умолчанию не подставлять. Пользователь выбирает её явно.
- Под полем новой даты справочно показывать название её дня недели с заглавной буквы и обновлять его при изменении даты. Подпись всегда располагать отдельной строкой под полем, а не сбоку. Для пустой или некорректной даты подпись скрывать. В справочной исходной дате также указывать день недели. Это вычисляемая подпись, отдельное поле данных не добавлять.
- Дата должна отличаться от исходной, быть допустимой и не раньше сегодняшнего дня.
- Запланированную будущую тренировку можно переносить и на более раннюю дату, если она не раньше сегодняшней. Например, с субботы на пятницу.
- Пропущенную тренировку можно перенести на сегодня или будущий день. Поскольку пропуск не бывает будущим, новая дата при этом будет позже исходной.
- Разрешать любую доступную неделю и день, где уже есть другие тренировки.
- Основная кнопка «перенести».
- После подтверждения изменить дату существующей записи, установить `planned`, сбросить факт до `null`, сохранить остальные пользовательские поля, `id` и `createdAt`.
- Исходная карточка исчезает из старого дня. Следа о пропуске и отдельной истории переноса не оставлять.
- Пересчитать план, итоговые сообщения и число неотмеченных тренировок исходной и новой недель.
- Перейти к неделе назначения, прокрутить к перенесённой карточке и подсветить её на 2 секунды.
- При переносе внутри недели показать «тренировка перенесена на {дата}. План гибкий, как после растяжки 🙂».
- При переносе между неделями показать «тренировка перенесена на {дата} и теперь входит в план этой недели 🌿».
- Отмена оставляет запись без изменений.

После переноса тренировка считается только по новой дате. Дубликат создавать нельзя. Поскольку выполненную тренировку переносить нельзя, сам перенос не добавляет фактических занятий и минут.

Это осознанный продуктовый компромисс, выбранный пользователем. Планировщик хранит актуальный план, а не историю дисциплины. После переноса пропуска старая неделя пересчитывается по оставшимся записям и может больше не содержать пропусков. Поэтому сообщения описывают текущие записи недели и не должны утверждать, что пользователь никогда не пропускала занятий. Статус «перенесено» и новая связанная карточка не добавляются.

### 7.7. Удаление

Удалять можно запись в любом состоянии и на любой дате. Подтверждение «удалить тренировку «{название}»? вернуть её после удаления не получится».

Кнопки «удалить» и «отмена». При подтверждении удалить только выбранную запись, сохранить данные, обновить день и итог недели, показать «тренировка удалена». Если удалён факт, он должен исчезнуть из итогов.

При отмене ничего не менять. Автоматическое восстановление и корзина не входят в первую версию.

### 7.8. Лимит тренировок

- В одном дне можно создать не больше 15 записей суммарно во всех состояниях. Это ограничение интерфейса, а не рекомендация по нагрузке.
- Перед созданием, сменой даты в редактировании и переносом проверять число записей в целевом дне. При изменении существующей записи не считать её дважды.
- Если целевой день заполнен, не менять данные и показать «в этом дне уже 15 тренировок. Выбери другую дату или удали лишнюю запись».
- У заполненного дня отключать «добавить тренировку» с видимой подписью «достигнут лимит 15 тренировок». Форма, открытая через недельное пустое состояние, всё равно проверяет выбранную дату при сохранении.
- У существующих карточек оставлять редактирование без добавления в этот день, ввод результата, удаление и перенос в другой доступный день.
- После удаления или переноса из дня снова разрешать добавление, если записей стало меньше 15.
- Отдельного недельного лимита не вводить. Защита от повторного сохранения из раздела 11.3 остаётся обязательной.
- Если ранее сохранённые валидные данные уже превышают этот лимит, не удалять их и не объявлять повреждёнными только по этой причине. Показывать их и разрешать операции, не увеличивающие число записей в переполненном дне.

### 7.9. Очистка всех данных

В подвале показывать второстепенную кнопку «очистить все данные». Она открывает диалог, но ничего не удаляет сама.

- Заголовок «очистить планировщик?».
- Текст «все тренировки за все недели будут удалены без восстановления».
- Обязательный checkbox «понимаю, что все тренировки будут удалены без восстановления», изначально не отмеченный при каждом открытии.
- Кнопки «удалить все тренировки» и «отмена».
- Удаление недоступно, пока checkbox не отмечен. Первоначальный фокус ставить на «отмена».
- Только после отметки checkbox и нажатия удаления записать пустой объект версии 1 в основной ключ по правилам раздела 11.3. Не очищать остальные данные браузера.
- После успешной записи закрыть диалог, выбрать текущую неделю и показать «планировщик очищен. Можно начать с нового плана 🌿».
- При отмене, Escape, крестике или нажатии на фон сохранить все записи.
- При ошибке записи сохранить прежние данные и оставить диалог с объяснением ошибки. Для повторной попытки не требовать повторного ввода, если диалог не закрывался.
- При уже пустом планировщике кнопку показывать отключённой с подписью «пока нечего очищать».
- При недоступном хранилище отключать действие. При повреждённых данных использовать тот же механизм с аварийным названием «начать заново» по разделу 12.4.

Это две отдельные осознанные проверки внутри одного подтверждения - отметка понимания последствий и нажатие удаления. Не показывать два вложенных диалога.

## 8. Переходы состояний

| Действие | Исходное состояние | Итоговое состояние | Фактические минуты |
| --- | --- | --- | --- |
| Создать | Записи нет | `planned` | `null` |
| Сохранить положительный результат | Любое | `completed` | Введённое значение |
| Отметить пропуск | `planned` | `skipped` | `0` |
| Заменить выполнение пропуском после подтверждения | `completed` | `skipped` | `0` |
| Сбросить результат после подтверждения | `completed` или `skipped` | `planned` | `null` |
| Перенести | `planned` или `skipped` | `planned` | `null` |
| Изменить основные поля или исправить запись | Любое | Без изменений | Без изменений |
| Удалить после подтверждения | Любое | Записи нет | Не учитываются |
| Очистить все данные после двух проверок | Любой набор записей | Все записи удалены | Не учитываются |

Все ограничения по дате из раздела 7 применяются и при вызове операций из JavaScript, а не только через доступность кнопок.

## 9. Недельный план и итог

Блок «итоги недели» доступен всегда, включая пустые, прошлые и будущие недели. Это единственный блок итогов, отдельный обзор прогресса не создавать.

Для выбранной недели вычислять следующие значения.

| Обозначение | Правило |
| --- | --- |
| `plannedCount` | Число всех записей, чьи запланированные даты входят в неделю |
| `plannedMinutes` | Сумма планируемых минут всех этих записей, независимо от состояния |
| `completedCount` | Число записей со статусом `completed` |
| `actualMinutes` | Сумма фактических минут записей со статусом `completed` |
| `skippedCount` | Число записей со статусом `skipped` |
| `pendingCount` | Число записей со статусом `planned` |
| `differenceMinutes` | `actualMinutes - plannedMinutes` |

Удалённые и перенесённые из недели записи в её план и факт не входят. Один выполненный объект равен одному занятию независимо от продолжительности и названия активности.

Визуально показать.

- «план» с количеством занятий и планируемым временем.
- «факт» с количеством состоявшихся занятий и фактическим временем.
- Разницу по времени, если в неделе есть записи.
- Одно основное поддерживающее сообщение.
- Пояснение о незаполненных результатах, когда оно применимо.

Использовать правильные окончания у слова «занятие», включая «1 занятие», «2 занятия», «5 занятий», «11 занятий», «21 занятие».

Разницу отображать следующим образом.

- Положительная - «больше плана на {продолжительность}».
- Отрицательная - «до планируемого времени {положительная продолжительность}».
- Нулевая - «по времени ровно по плану».
- Пустая неделя - разницу не показывать, план и факт равны нулю.

Не называть незавершённую неделю проваленной и не приравнивать равенство суммарных минут к выполнению каждой тренировки.

Пояснения по календарному периоду.

- Будущая неделя - «это план будущей недели. Результаты можно будет отметить начиная с дат занятий».
- Текущая неделя - «промежуточный итог»; при наличии `planned` дополнительно «ещё без отметки - {число}».
- Прошлая неделя с `planned` - «есть тренировки без отметки, итог пока неполный».
- Прошлая неделя без `planned` - «все тренировки недели отмечены».
- У пустой недели не показывать пояснение о незаполненных отметках.

Планируемое время пропущенных тренировок остаётся в плане, пока запись не удалена или не перенесена. Фактическое время пропусков равно нулю. Неотмеченные тренировки не считаются пропусками.

## 10. Мотивация и тексты

Сообщения не требуют интернета или генеративной модели. Все фразы заданы в `script.js`. Тон дружелюбный, на «ты», без стыда, оценки тела и давления увеличить нагрузку.

Не обещать медицинский эффект и не советовать тренироваться через боль или усталость. Юмор касается планов, календаря и бытовых ситуаций.

### 10.1. Сообщения отдельной тренировки

После сохранения результата показывать одну фразу соответствующей категории. Та же фраза отображается в карточке выполненной или пропущенной тренировки. У запланированной карточки мотивационная фраза результата отсутствует.

| Категория | Условие | Допустимые фразы |
| --- | --- | --- |
| Пропуск | `skipped` | «одна пропущенная тренировка не обнуляет твои усилия. Продолжить можно в другой день 🌿»; «сегодня не сложилось. План можно поправить, а себя поддержать 🤍»; «календарь выдержит перенос. Он вообще довольно спокойный 🙂» |
| Больше плана | `completed`, факт больше плана | «ты уделила движению больше времени, чем планировала. Хорошая работа! ✨»; «план получил бонусные минуты. Ты молодец 🌿»; «сегодня получилось больше задуманного. Пусть отдых тоже найдётся в расписании 🙂» |
| Ровно по плану | `completed`, факт равен плану | «тренировка по плану выполнена. Хорошая работа! 🙌»; «план и факт встретились. Красивое совпадение ✨»; «ты сделала то, что запланировала. Можно поставить довольную галочку ✅» |
| Меньше плана | `completed`, факт меньше плана | «ты нашла время для движения. Даже короткое занятие считается 🌿»; «пусть минут меньше, зато занятие состоялось. Это уже результат 🤍»; «сегодня получилась компактная версия тренировки. Она тоже идёт в зачёт 🙂» |

Выбирать вариант детерминированно и без собственного хеш-алгоритма. Для отдельной карточки взять строку `id`, сложить значения её UTF-16 единиц через `charCodeAt` и взять остаток от деления суммы на число фраз соответствующей категории. Категория определяется результатом, но не входит в расчёт индекса. При обычной перерисовке фраза не меняется.

### 10.2. Основное сообщение недели

Проверять условия строго сверху вниз. Первая подходящая строка определяет категорию.

| Приоритет | Условие | Фразы категории |
| --- | --- | --- |
| 1 | `plannedCount = 0` | «выбери удобный день и запланируй первую тренировку 🌿»; «календарь пока свободен. Добавим немного движения? 🙂» |
| 2 | Неделя будущая | «план готовится. Оставь в нём место и для отдыха 🌿»; «будущая неделя уже получила немного движения. Хорошее начало ✨» |
| 3 | `pendingCount > 0` | «не всё ещё отмечено. Запиши результат, когда будет удобно 🤍»; «план живой, а не высечен в камне. Продолжай в своём темпе 🌿» |
| 4 | `skippedCount > 0`, `completedCount = 0` | «на этой неделе не получилось позаниматься. Можно начать снова с одного удобного дня 🤍»; «неделя сложилась иначе. Поддержи себя и поправь следующий план 🌿» |
| 5 | `skippedCount > 0`, `completedCount > 0` | «были пропуски, но были и занятия. Твои усилия никуда не исчезли 🌿»; «не всё пошло по плану, но движение было. Календарь не требует идеальности 🙂» |
| 6 | Все отмечены, пропусков нет, факт больше плана | «ты уделила тренировкам больше времени, чем планировала. Отличная работа! ✨»; «на этой неделе у плана появились бонусные минуты. Ты молодец 🙌» |
| 7 | Все отмечены, пропусков нет, факт равен плану | «все занятия отмечены, время по плану. Хорошая работа! ✅»; «план и факт подружились. Можно порадоваться результату ✨» |
| 8 | Все отмечены, пропусков нет, факт меньше плана | «ты отметила все занятия и нашла время для движения. Это ценно 🌿»; «занятия состоялись, даже если были короче. План можно подстроить под жизнь 🙂» |

При наличии пропусков не выбирать сообщение о полном выполнении недели, даже если одна длинная тренировка компенсировала пропущенные минуты.

Выбор фразы в категории делать тем же способом суммирования значений `charCodeAt`, но по строке `weekStart` в формате `YYYY-MM-DD`. Категорию пересчитывать при изменении данных или календарного периода. Индекс внутри категории зависит только от даты начала недели. Отдельный архив сообщений не хранить.

### 10.3. Служебные сообщения

- Успешные уведомления показывать на 6 секунд в спокойном блоке без перекрытия кнопок. После удаления блок получает фокус только при необходимости для доступности, обычно фокус остаётся в интерфейсе.
- Сообщения ошибок поля показывать до исправления или закрытия формы.
- Сообщения ошибок хранения показывать постоянно до успешной повторной проверки.
- Использовать `aria-live="polite"` для результатов и уведомлений, ошибки сохранения дополнительно обозначать через `role="alert"`.
- Не использовать звук, вибрацию, конфетти и полноэкранные поздравления.

## 11. Модель данных и сохранение

### 11.1. Хранимый объект

Единственный основной ключ localStorage - `plannerMotivator.data`.

Объект сериализуется в JSON и содержит.

| Поле | Тип и значение |
| --- | --- |
| `version` | Число `1` |
| `workouts` | Массив тренировок |

У каждой тренировки следующие поля.

| Поле | Требования |
| --- | --- |
| `id` | Уникальная непустая строка, неизменяемая в течение жизни записи |
| `title` | Нормализованное название, от 1 до 80 Unicode-кодовых точек |
| `date` | Допустимая дата `YYYY-MM-DD` |
| `plannedMinutes` | Целое число от 1 до 1440 |
| `actualMinutes` | `null`, `0` или целое число от 1 до 1440, строго согласно состоянию |
| `status` | `planned`, `completed` или `skipped` |
| `createdAt` | Неотрицательное целое число миллисекунд момента создания |
| `updatedAt` | Неотрицательное целое число миллисекунд последнего изменения |

Использовать `crypto.randomUUID()`, если доступно. При недоступности сформировать строковый идентификатор из времени и случайной части, проверить отсутствие совпадения в массиве и при совпадении сгенерировать заново. Не делать доступность `randomUUID()` обязательным условием запуска.

Состояние выбранной недели, открытой формы, итоги и сообщения не сохранять. Историю переносов, исходные даты перенесённых тренировок и резервные копии не создавать.

Отсутствие экспорта и импорта является прямым выбором пользователя для первой версии. После удаления данных или их утраты приложение не обещает восстановление истории. Не добавлять скрытые резервные файлы или кнопки копирования как обход этого решения.

### 11.2. Чтение

1. Попытаться получить данные из ключа в обработчике ошибок.
2. Если ключ отсутствует, использовать пустой массив версии 1, но не записывать пустой объект автоматически.
3. Если ключ существует, разобрать JSON и проверить версию, структуру, уникальность `id`, типы, значения и согласованность состояний.
4. Наличие неизвестных дополнительных полей не считать повреждением, но не использовать их в расчётах.
5. При ошибке чтения действовать по разделу 12. Не заменять ошибочные данные пустым списком с последующим автоматическим сохранением.

### 11.3. Запись и изменения

- Перед первой записью проверить доступность хранения временным ключом `plannerMotivator.storageProbe`, прочитать записанное значение и удалить временный ключ. Не трогать чужие ключи.
- Каждое изменение выполнять над отдельной копией данных, валидировать результат, сериализовать и записывать одним вызовом `setItem` основного ключа.
- Только после успешной записи применять новую копию к текущему состоянию страницы и сообщать об успехе.
- Если запись не удалась, прежние данные, карточки и итог остаются прежними. Открытая форма сохраняет введённые значения.
- Во время сохранения блокировать повторное нажатие основного действия.
- Не использовать `localStorage.clear()`.
- Не добавлять запись при отмене формы, неизменённом результате или повторном событии одного действия.
- Сохранять сразу после каждого изменения, без отдельной кнопки «сохранить всё».

### 11.4. Несколько вкладок

Первая версия рассчитана на редактирование в одной вкладке за раз. Одновременное редактирование в нескольких вкладках не является поддерживаемым сценарием.

Использовать один обработчик события `storage`. Обрабатывать только изменение основного ключа в localStorage, а также событие с `key = null`, означающее очистку хранилища. Изменения временного проверочного ключа и чужих ключей игнорировать.

- Если диалог не открыт, перечитать и проверить данные по разделу 11.2, затем обновить выбранную неделю без её переключения и без прокрутки наверх.
- Если открыт диалог формы или подтверждения, не стирать его содержимое. Установить один флаг ожидаемого обновления, отключить все действия сохранения и удаления в нём, показать «данные изменились в другой вкладке. Закрой окно и повтори действие».
- После закрытия такого диалога загрузить последнее состояние хранилища и обновить страницу. Для повторного действия пользователь заново открывает форму. Слияние черновика и внешних изменений не выполнять.
- Если новое состояние невозможно прочитать, применять правила раздела 12, а не продолжать операции со старой копией.
- Вкладка, сохранившая изменение сама, обновляет интерфейс сразу после записи, не ожидая события `storage`.

Событие localStorage поступает другим вкладкам с тем же origin, а не вкладке, выполнившей запись. Эта возможность не является системой разрешения одновременных конфликтов. При практически одновременной записи последняя успешная запись может заменить предыдущую. Не вводить ревизии, сравнение сериализованных строк перед каждой записью, блокировки или слияние версий. [Источник - MDN, событие storage](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event).

## 12. Ошибки и восстановление

### 12.1. Ошибки ввода

Использовать следующие сообщения.

| Ошибка | Текст |
| --- | --- |
| Пустое название | «напиши название активности» |
| Название длиннее 80 символов | «название должно быть не длиннее 80 символов» |
| Пустая, несуществующая или недопустимая дата | «выбери корректную дату от 01.01.1900 до 31.12.2099» |
| Нецелые или отрицательные часы и минуты | «введи целое неотрицательное число» |
| Минуты больше 59 | «минуты должны быть от 0 до 59» |
| Продолжительность больше 24 часов | «продолжительность должна быть не больше 24 часов» |
| Нулевой план | «запланируй хотя бы 1 минуту» |
| Нулевой факт | «укажи время больше нуля или отметь пропуск» |
| Результат для будущей даты | «результат можно отметить начиная с даты тренировки» |
| Будущая дата для выполненной или пропущенной записи при редактировании | «у отмеченной тренировки дата не может быть в будущем» |
| Перенос на исходную дату | «выбери другую дату» |
| Перенос в прошлое | «перенести можно на сегодня или будущую дату» |
| День заполнен | «в этом дне уже 15 тренировок. Выбери другую дату или удали лишнюю запись» |

При нескольких ошибках показать все, а фокус установить на первой по порядку полей. Не сохранять частично валидные данные.

### 12.2. Хранилище недоступно

Показать «браузер не разрешает сохранять данные. Изменения сейчас недоступны. Проверь настройки браузера и попробуй снова» и кнопку «проверить снова».

Если ранее данные уже успешно загружены, разрешить их просмотр и переключение недель, но отключить создание и изменение до успешной проверки. Если чтение не удалось при запуске, показать «не удалось загрузить тренировки», не утверждать, что тренировок нет.

Не переходить незаметно на временное хранение в памяти и не сообщать о сохранении без записи.

### 12.3. Неудачная запись

Показать «не удалось сохранить изменения. Они не применены. Проверь доступное место и настройки браузера, затем попробуй снова».

Оставить исходные данные без изменений. Если форма открыта, сохранить её ввод и разрешить повторное сохранение. У удаления, пропуска и сброса оставить исходную карточку и предложить повторить действие.

### 12.4. Повреждённый формат или неизвестная версия

Показать «сохранённые данные не удалось прочитать. Они не изменены» либо «эти данные созданы другой версией приложения. Они не изменены».

Отключить обычные операции над данными. Доступны «проверить снова» и аварийное действие «начать заново». В этом состоянии оно заменяет обычную очистку в подвале.

«начать заново» использует тот же диалог, checkbox и последовательность действий, что общая очистка в разделе 7.9. Заголовок «удалить непрочитанные данные?», основной текст «сохранённые данные этого планировщика будут удалены без восстановления», кнопка «удалить данные и начать заново». Checkbox и отмена остаются обязательными.

Только после подтверждения и успешной записи пустого валидного объекта разблокировать приложение. Не менять никакие другие ключи браузера. Начало заново не является резервным копированием.

## 13. Дизайн и доступность

### 13.1. Палитра и компоновка

Правила регистра уточнены пользователем после выполнения первого шага и имеют приоритет над регистром примеров текстов в других разделах этого документа.

- Названия дней, состояний, полей, обычных кнопок и предложения интерфейса начинаются с заглавной буквы.
- Прописными буквами отображать название приложения, диапазон недели, «Итоги недели», «План», «Факт» и заголовки диалогов.
- Прописными буквами отображать основные кнопки добавления, планирования, сохранения и текущей недели, а также подтверждения опасных действий. Второстепенные кнопки навигации, редактирования карточки и отмены остаются с заглавной первой буквой.
- Для прописного отображения использовать CSS `text-transform: uppercase`. Это визуальное оформление, а не изменение данных.
- Названия тренировок в карточке и доступных именах показывать с заглавной первой буквой; если перед названием есть эмодзи или цифры, сделать заглавной первую буквенную позицию. Остальные буквы сохранять как введены пользователем. Хранимое название и значение поля редактирования не переписывать ради оформления.
- Даты и единицы длительности в обычном тексте сохраняют естественный регистр, например «14 октября» и «1 час». На узком экране длинные прописные надписи переносятся и не создают горизонтальную прокрутку.

Задать цвета через CSS-переменные.

| Роль | Цвет |
| --- | --- |
| Фон страницы | `#FAF7F2` |
| Основные карточки и формы | `#FFFFFF` |
| Фон нечётных дней недели | `#F0F4EE` |
| Фон чётных дней недели | `#FFFFFF` |
| Основной текст | `#2D3430` |
| Второстепенный текст | `#59645D` |
| Основная кнопка | `#456651` с белым текстом |
| Кнопки пропуска | `#B43C46` с белым текстом; наведение `#96313A` |
| Кнопки переноса | `#F4D77E` с текстом `#2D3430`; наведение `#E9C65D` |
| Мягкий шалфейный акцент | `#DDE9DE` |
| Лавандовый акцент | `#E8E1F0` |
| Пудровый акцент пропуска | `#F3E0DC` |
| Границы | `#D8DCD4` |
| Ошибка и удаление | `#8B3434` |

На пастельных фонах использовать тёмный текст. Карточку пропущенной тренировки оформлять мягким пудровым акцентом. По уточнению пользователя от 17.10.2026 кнопки «Пропустить» и «Отметить пропуск» имеют красную заливку с белым текстом, а «Перенести» в карточке и форме - жёлтую заливку с тёмным текстом. Проверить читаемость в обычном состоянии и при наведении.

- Слева от текста кнопки «Отметить результат» и статуса «Выполнено» показывать крупную галочку. Галочка декоративная, доступное имя действия сохраняется, нажатие на галочку и текст вызывает одно и то же действие. Статус «Выполнено» остаётся информационной отметкой.
- В каждой карточке справа от основных сведений, под общим центрированным названием, показывать подходящий виду активности символ. Использовать встроенные эмодзи без внешних изображений и дополнительных файлов. Название остаётся свободным текстом; отдельное поле выбора вида активности не добавлять.
- Подбирать символ по названию без учёта регистра и различия «е» / «ё». Примеры - бег и пробежка получают бегущего человека, прогулка с собакой - собаку и мяч, теннис - символ тенниса. Настольный теннис отличать от обычного; упоминание собаки проверять раньше общей прогулки. Для остальных знакомых видов использовать соответствующие спортивные символы; если название не распознано, показывать нейтральный символ 💪.
- Символ не хранить в localStorage, пересчитывать при изменении названия. Скрывать его от повторного озвучивания через aria-hidden. На узком экране он не перекрывает текст и кнопки, длинные названия переносятся.

- Системный шрифт. Размеры шрифтов задавать в `rem`, основной текст не меньше `1rem`; у корневого элемента использовать `font-size: 100%`, без фиксации 16 px. При стандартном размере браузера 16 px это соответствует прежнему ориентиру, а пользовательская настройка размера шрифта остаётся действующей.
- Для межстрочного интервала использовать безразмерное значение, для основного текста `1.5`. Отступы и скругления можно задавать в `rem`, но ширины проверяемых экранов и минимальные области нажатия из этого ТЗ остаются ориентирами в CSS px. [Источник - MDN, относительные единицы длины](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length).
- По последующему уточнению пользователя от 17.10.2026 общая рамка охватывает весь день - его название, дату, отметку «Сегодня», кнопку добавления и все карточки активностей этого дня либо пустое состояние. Отдельную вложенную рамку только вокруг названия дня и даты убрать. При добавлении и переносе карточек общая рамка подстраивается по высоте.
- Для фона блоков дней использовать ровно два чередующихся нейтральных цвета. Понедельник, среда, пятница и воскресенье - бледно-зелёный #F0F4EE; вторник, четверг и суббота - белый #FFFFFF. Чередование относится ко дням недели и сохраняется при смене недели независимо от числа тренировок. Внутренние карточки остаются белыми, а пустое состояние не вводит третий фоновый цвет. Отметки статусов и согласованные цвета кнопок сохраняются; сегодняшний день дополнительно отличается подписью и границей, без третьего фона дня.
- Если название дня с датой и кнопка добавления не помещаются в строку, переносить кнопку ниже с выравниванием вправо. Шрифт кнопки, её внутренние отступы и минимальная высота сохраняются; кнопка может занимать доступную ширину блока.
- Название активности располагать по центру всей карточки над сведениями и символом. Размер названия равен 1,5 базового размера текста карточки - 1.5rem. Строки «План» и «Факт» вместе со временем показывать в 1,5 раза меньше базового текста - calc(1rem / 1.5). При базовом размере 16 px это соответственно 24 px и около 10,67 px. Малый размер применяется только к этим справочным строкам по запросу пользователя; размеры текста и областей нажатия кнопок остаются прежними. Остальные размеры и настройки увеличения текста сохраняются.
- Основной контент ограничить шириной 760 px и центрировать.
- Боковые отступы на телефоне 16 px, у диалогов не меньше 12 px.
- Скругление карточек 16 px, кнопок и полей 12 px.
- Между днями 20-24 px, внутри карточки 12-16 px.
- Элементы управления высотой не меньше 44 px, с достаточными промежутками.
- Кнопки карточек переносятся на новые строки, не выходят за ширину экрана.
- Блок плана и факта допускает две колонки при достаточной ширине, на узком экране одну.
- Проверить ширины 320, 375, 390, 430, 768 и 1280 px. Горизонтальная прокрутка недопустима.
- Длинные названия и непрерывные строки переносить внутри карточки.
- Диалог не должен выходить за высоту экрана. Поля и основные кнопки должны оставаться доступны при открытой экранной клавиатуре.

### 13.2. Доступность

- Указать `lang="ru"` и viewport для мобильных устройств.
- Использовать семантические заголовки, настоящие кнопки и формы.
- У каждого поля должна быть видимая подпись, не только placeholder.
- Все действия доступны с клавиатуры, с видимым фокусом.
- Использовать модальное поведение нативного `<dialog>`, не писать отдельный собственный перехват Tab без выявленной необходимости. Проверить, что фокус не уходит в фон страницы, при открытии формы направлен на первое редактируемое поле, при открытии опасного подтверждения - на «отмена», при закрытии возвращается по правилам раздела 7.
- Связать диалог с заголовком через `aria-labelledby`, а подтверждение удаления дополнительно с пояснением через `aria-describedby`. Кнопка «✕» обязательна и имеет доступное имя «закрыть».
- Не запрещать масштабирование страницы.
- Системные эмодзи не являются единственным смысловым обозначением кнопок.
- При `prefers-reduced-motion` отключать плавную прокрутку и анимацию подсветки. Статический акцент допускается.

## 16. Требования к реализации и проверке качества

- Разделить функции работы с датами, проверки ввода, расчётов, хранения и отображения. Не дублировать правила вычисления в обработчиках разных кнопок.
- Использовать одну функцию расчёта итогов выбранной недели и одну таблицу правил мотивационных сообщений.
- Выводить пользовательские строки через `textContent` или безопасное создание текстовых узлов. Не вставлять названия в HTML-строки через `innerHTML`.
- Вся работа с localStorage, разбором JSON и сериализацией должна иметь обработку ошибок.
- Не хранить итоги как отдельные значения, которые могут разойтись с тренировками.
- Не менять данные при одном только отображении недели или наступлении даты.
- При повторной отрисовке не накапливать обработчики событий.
- Использовать `inputmode="numeric"` для длительности и нативный `input type="date"` по разделу 5.2. Проверки в JavaScript обязательны даже при HTML-ограничениях.
- Проверить обычные режимы актуальных стабильных Chrome и Edge на компьютере, Chrome на Android и Safari на iPhone, когда эти устройства доступны. Фиксировать фактически проверенные браузер, версию и способ открытия; не заявлять проверку недоступных устройств.
- Проверить отказ хранилища, повторное открытие страницы и сохранение реальных изменений в целевом способе запуска.
- Проверить, что при доступном хранилище все сценарии работают без сетевых запросов и ошибок в консоли.
